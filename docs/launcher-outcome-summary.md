## 统一结果

`GET /api/launcher/stats?from=YYYY-MM-DD&to=YYYY-MM-DD&view=problems` 的顶层及每个问题新增 `outcomes`。看板原有新增安装范围继续使用 `scope=new_installations&window_days=7`。

| 字段 | 含义 |
| --- | --- |
| `affected_installations` | 所选范围曾遇到问题的独立安装环境数 |
| `later_succeeded_installations` | 该环境所涉问题对应的操作均有后续同类成功结果 |
| `latest_failed_installations` | 至少一项问题对应操作的最近结果明确失败 |
| `in_progress_installations` | 没有上述最近失败，但仍有相关操作正在处理且未失去联系 |
| `unconfirmed_installations` | 没有上述失败或进行中证据，仍缺少可确认成功的结果，包括失去联系、取消、中断等 |

后四项互斥，相加等于第一项。一个环境跨多个问题，优先归入最近失败、处理中、待确认，全部相关操作后续成功才计入成功；不能直接把各问题行的受影响数相加。

后续结果来自查询时点最新收到的同类操作，可跨日期和版本，不代表用户电脑此刻状态，也不证明底层缺陷已修复。安装后的服务启动成功不替代安装／更新成功；没有终态不能写成失败或已恢复。技术分组不是已经定位的独立 Bug 数。

## 展示与汇报

- 主展示使用安装环境结果，不显示原始错误事件数或失败操作总数。看板将处理中与未知合为“结果待确认”，详情分别列出。
- 问题列表按已有技术依据合并，显示原因、发生环节、受影响环境及后续结果。过程次数放入折叠“重试过程”，保留追溯。
- 顶层结果在分页前计算，全局汇总不受当前问题页或当前环境页影响。
- 旧接收端没有 `outcomes` 时，只展示可信的受影响总数；其他汇总显示缺失，不从单页、重叠问题或操作次数推算。
- 旧 `summary`、`attempts` 等字段为兼容诊断读取而保留，不作为运营主指标。看板适配器将过程次数放在 `issues[].diagnostics`。

汇报入口为 `scripts/report-launcher-outcomes.mjs`。以环境变量提供原有查询密钥，日期作为命令参数；不在命令行填写密钥。脚本只读取统一 `outcomes` 并输出汇总；接口未具备该字段时明确失败，不回退输出几百次操作错误。无自动调度或补造数据。
