# 官网安装包下载

范围：网页下载入口及现有 Cloudflare Worker；安装包内容、启动器更新、数据库结构、页面布局不变。

## 当前实现：SF 优先，同文件切换 GitHub

1. 网页调用 `/api/download/:platform?format=json`，沿用现有安装包定位与缓存。JSON 的 `url` 是安装包身份信息，不代表文件已下载。
2. 网页从已校验的地址提取发布标签和文件名，调用同一 Worker 的 `/api/download/:platform?asset=<发布标签>/<安装包文件名>`。标签、平台和文件名严格匹配，只能访问本项目的 GitHub/SF 路径，不能中转任意网址。
3. Worker 先以 GET 请求 SF 的同文件地址，跟随最多六次同路径官方镜像跳转。读取实际文件的开头，检查响应状态、类型、范围、长度及明显错误页；Windows 从文件开头读取时还检查 MZ 标记。
4. SF 在开始传输前返回403/404/5xx、8秒内未完成响应和初始数据读取、返回空文件/错误页或非法跳转，Worker 改请求 GitHub 的同标签、同文件名。GitHub 的准备阶段同样限时8秒；不跳转发布页，不因换源另选旧安装包。
5. 文件采用流式中转，保留附件文件名、文件长度和206范围响应；不会把整个 EXE/DMG 缓存在 Worker 内存。准备超时在初始检查通过后解除，正常的大文件传输不会被8秒计时中断。
6. 两个来源均失败时返回503及中文说明。错误页通过受限 `postMessage` 通知原下载页；前端检查来源、窗口、平台及文件身份，显示错误和30秒冷却，仍用原下载按钮，不新增重试按钮。

没有 JavaScript，或通过新标签打开原按钮时，`/api/download/:platform` 会自行定位安装包，并经过同一条 SF → GitHub 中转路径。正常 GET 不再返回外部302。HEAD 仅读取一个字节验证文件，再返回文件长度，不下载整个安装包。单段 Range 请求可用于续传；非法或多段 Range 返回416。

## 保留的安装包定位规则

定位阶段仍使用 GitHub 发布元数据、现有种子、15分钟缓存、健康记录和30秒复查间隔；GitHub 元数据不可用时可以读取 SF 的 `channels/stable.json`。数据库不可用时仍允许独立定位。定位检查中的 HEAD 不作为传输成功证据，也不决定实际下载的优先来源。

这次换源只固定一次请求中的安装包身份，不改变既有的历史版本扫描、组件版本或启动器自动更新策略。新安装包仍由现有发布定位机制发现，网页不写死本次安装包版本。

## 统计与边界

- `download_ready` 仍表示取得有效安装包地址并提交中转请求，不是文件接收完成；提示改为“已提交下载请求”。
- 两个来源均失败且错误消息到达页面时，补报 `download_failed`。同一错误消息只处理一次；旧事件和统计结构不改。
- 传输已经开始后不能把另一份文件直接拼接到响应里。中途网络断线会终止传输，用户需要重新点击，或由下载工具发起 Range 续传；不承诺无缝恢复。
- 初始检查不是整包 SHA-256 校验。不能仅凭地址、长度或文件开头声称文件内容完全一致。

## 验证记录（2026-10-09，本地，尚未部署）

- 下载定位、前端和中转的47项针对性检查通过，包含 SF 健康时不访问 GitHub、三个平台 SF403后的同文件切换、响应/首段超时、错误页、空文件、HEAD、Range、非法目标和中途断线。
- 本地 Wrangler/Workerd 实际从 SF 读取三个安装包的前512字节，均返回206；受控注入 SF403后，同一运行时从 GitHub 读取三个对应文件，均返回206。发布标签、文件名、总长度及这512字节相同。这不是整包下载或安装验收。
- 本机直接访问 SF 曾返回403，但 Worker 中转实测可读取，尚不能认定是 SF 额度耗尽。
- 尚未在真实浏览器验收点击下载或在官网部署。

## 发布与回退

发布须经用户明确授权。先备份当前生产版本和受影响文件，确认没有覆盖其他尚未提交的统计/接收端修改，再一起发布网页脚本与 Worker。无需数据库迁移。发布后检查三个 JSON 定位接口、实际文件范围响应、首页脚本及真实浏览器下载开始情况。

回退时必须同时还原网页脚本与 Worker。旧版直接跨域下载仍可能隐藏 SF 失败，不应把回退称为故障已解决。
