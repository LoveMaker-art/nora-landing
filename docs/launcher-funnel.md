# 启动器新安装漏斗查询

状态（2026-10-01）：本地实现，功能代码尚未提交、合并或部署。供开发者定时取数，复用现有 D1 数据与上报事件，不新增监控页面或模型配置埋点，不绑定网页访客，也不监控游玩内容。

## 接口

`GET /api/launcher/stats?from=2026-09-25&to=2026-09-30&view=funnel&window_days=7`

使用现有 `Authorization: Bearer <STATS_READ_KEY>`，仅供开发者的受信任取数脚本或服务。读密钥不进入启动器或公开网页。from/to 是首次打开批次的日期，上海时区，含起止日期，最多 93 天。window_days 为每个安装环境从首次打开起的观察天数，默认 7，可选 1 到 30。

可筛选 platform、launcher_version、product_version，按首次打开记录的属性筛选，后续升级不改变批次归属。不能同时传 operation_id、installation_id 或 offset。原接口不加 view 的行为保留。

## 四个阶段

| summary 字段 | 判定 |
|---|---|
| first_opened | 首次登记 cohort=new 的独立安装标识 |
| install_started | 同一标识在观察期内有 install 的 operation_started |
| install_completed | 同一个已开始安装任务有 succeeded 的 operation_finished |
| runtime_ready | 已有安装完成证据，并在观察期内报告 runtime_first_ready |

每个标识每个阶段只计一次，不用事件次数当人数。existing、unknown、更新和修复不计入新增安装阶段。事件按 sequence 排序，补报到达顺序不能改变结果。首次运行就绪在当前启动器中可能早于安装终结事件发出，查询允许同一观察期内两个结果先后到达，不误判缺失。

缺少首次登记或开始证据时，不补造对应阶段。运行就绪不是游玩成功，下载完成仍无法观测。统计样本只包含成功送达的基础事件；基础统计不受详细诊断开关控制，关闭详细诊断仍能计入漏斗。

## 返回结果

- summary：四个阶段的独立安装环境数。
- stages：各阶段人数及相对上一步的 conversion_from_previous；分母为零时返回 null。
- daily：按首次登记日分组的四阶段数据、observing 和 finalized。没有样本的日期不返回行，调用方需要时可补齐空日期。
- observation：观察天数、观察中的安装环境数、观察窗结束的数量；迟到补报仍可能修订历史。
- states：观察窗内最后状态的数量。
- states_by_stage：按已到达的漏斗阶段细分状态，用于定位卡点。
- durations：安装任务阶段的结束样本数、median_ms 和 p90_ms。包含成功、失败、取消和中断的已结束阶段；不代表所有用户停留时长，未结束及漏报阶段没有样本。
- failures：安装失败任务数、受影响安装环境数，按阶段和错误码分组。后来重试成功的失败任务仍留在这里，不代表环境最终失败。

状态包括 ready、waiting_for_user、running、slow、possibly_stalled、contact_lost、failed、cancelled、interrupted、awaiting_next_step、not_continued。

任务超过 2 分钟无新心跳才标记 contact_lost，不能算失败。等待用户的记录保持 waiting_for_user，不因没有任务心跳而算失联。没有正在运行的任务或明确等待记录时，观察中显示 awaiting_next_step；观察窗结束后仍未继续显示 not_continued。后者不证明用户永久放弃。

这些是观察窗截止时的最后可见状态，不是电脑当前在线状态。辅助检查、报错证据、更新和修复不会覆盖安装流程状态。统计不额外输出等待配置的模型细分。

## 时间与准确性

查询观察每个标识的 `[首次打开, 首次打开 + window_days]`，尚未结束时截止查询时刻。后续事件可以在 from/to 之外，只要属于观察窗，仍计入该批次。不能把按事件发生日聚合的成功数除以当天首次打开数。

观察中批次应明确标注“观察中”，最终转化比较应选足够成熟且同观察长度的批次。当前返回的总体转化包含观察中样本，不应标为最终流失率。

处理最多 50000 条相关事件；超出返回 422 cohort_too_large，要求缩短日期或按平台筛选，不返回截断后的错误漏斗。身份、日期、字段权限沿用现有规则。清除本地标识、停收、断网及事件队列淘汰都可能影响数据。
