# 诺拉人格设计

通过对话帮助用户设计自己的诺拉，输出完整 SOUL.md 文档和试聊题，由用户复制更换。先理解用户希望怎样相处，再把性格转化为具体反应；本技能只负责文稿，不代替用户应用人格。

## When to Use

- 用户要求设计、重构或调整诺拉的性格、语气、称呼和相处方式。
- 用户希望借鉴某个角色，或觉得现有人格空泛、缺少特点，需要具体化。
- 用户要检查或试聊一份人格草稿。
- 普通闲聊、设计世界里的角色卡、修改模型供应商和故障诊断不属于本技能。

## Prerequisites

设计与文本试聊不需要 API Key、酒馆在线或安装额外程序。只使用用户当前提供的人格与偏好；需要原稿而当前不可见时，询问用户或按已有授权读取指定文件，不检索私人历史填充人设。

## How to Run

通过 `skill_view(name="nora-persona-designer")` 加载。在支持技能斜杠命令的会话中，也可使用 `/nora-persona-designer 帮我设计自己的诺拉`。

参考文件通过本技能的 `file_path` 按需读取，例如：

`skill_view(name="nora-persona-designer", file_path="references/design-guide.md")`

## Procedure

1. **确定本次范围。** 区分讨论方向、修改局部、完整重构和试聊。沿用用户已确认的要求；局部修改先明确保留什么，不趁机重写整个人格。普通用户无需先填长表，每轮只问一两个会影响方向的问题。完成条件：知道用户希望得到什么，以及哪些现有特点要保留。
2. **确定内核。** 了解相处定位、主要气质、在意的事和兴趣。参考角色是可选项：明确借鉴哪些具体特点、不继承哪些设定，以及诺拉自己的区别。陌生角色先请用户给代表场景，或用已可用的 `web_search`／`web_extract` 核对官方资料；不凭角色名编造设定，也不强迫使用参考角色。完成条件：能用一句具体的话描述她，并区分已确认选择与建议。
3. **写出可辨认的反应。** 为主要特点写清“场景 → 反应 → 收住的条件”，加入具体喜好和少量自然的性格张力。幽默、好胜、别扭等特点不能变成现实任务中的敷衍或失实。用户不知如何选择、性格互相冲突或缺少辨识度时，读取 [设计指导](references/design-guide.md) 中的相应部分。完成条件：主要特点都有行为表现，冲突有情境区分，重大未知未被当成已确认设定。
4. **生成可审阅草稿。** 读取 [SOUL 模板](templates/SOUL.md)，用用户的选择填成独立可理解的完整文本，删除占位符及无用小节。围绕用户选定的兴趣和性格，写三到五段原创例句，覆盖轻松交流、意见不同及认真求助／犯错；不套用参考资料的现成台词。局部修改只改用户选定的部分。说明重要变化，不把自己的提议写成用户偏好。试聊题与操作说明放在文稿之外，避免用户复制进人格正文。完成条件：交付完整可复制文本，或在方向尚待选择时交付明确标注的候选，不冒称已经确定。
5. **检查或试聊。** 对照 [设计指导中的试聊题](references/design-guide.md#试聊检查) 检查辨识度、相处舒适度、一致性和现实任务的可靠性。用户要求演示时，明确标为“按草稿模拟”，不把它当成已安装人格或跨会话效果验证。每次针对一个问题调整，保留其他已确认特点。完成条件：说明本轮检查了什么、用户还需判断什么，不虚构测试结果。
6. **交付文档，由用户更换。** 在回复中用一个独立的 Markdown 代码块提供完整 SOUL.md，不能用省略号、差异片段或“其余不变”代替全文。代码块外简短说明：复制完整文稿 → 打开已有的“人格设定” → 粘贴并保存；没有该入口时，由用户按自己的部署说明更换实际使用的人格文件，不猜固定目录。用户认可文稿仅代表定稿，不触发保存、替换或重启；要求代为应用时，也说明本技能采用用户手动更换的方式。只有用户另行要求下载文档，才可将副本导出到已确认的独立位置，不写活动人格。完成条件：用户能直接复制或取得完整文档，明确知道需自己更换，当前人格及其他数据保持不变。

## Pitfalls

- 本技能设计的是诺拉日常人格。没有用户明确选择时，不强制安静或元气，不套用某一角色的身份、恋爱关系、口癖或全部世界观。
- 人格例句是表达示范，不是真实记忆、执行回执或必须复读的台词。用户当前明确需求优先于旧偏好；虚构故事不变成用户的现实经历。
- 认真询问身份、能力或经历时保持诚实。相处不索取排他、持续回应或现实关系承诺；人格不赋予新工具、永久记忆或额外权限。
- 保留聊天、角色、世界、配置和私人内容；不改运行 AGENTS、模型配置或记忆原件，不借人格设计扩大操作授权。
- 对话示例、文本保存和运行时采用是不同结果。不同模型及前文可能影响表现，不承诺下一条消息立即完全生效。

## Verification

交付前核对：用户选定的特点与保留项已落实；没有未填占位符或互相冲突的绝对要求；例句能体现所选性格且不编造现实事实；角色参考的继承与舍弃清楚；没有凭据、机器固定路径或活动人格写入。最终回复给出完整成稿、主要变化和文稿外的少量试聊题，明确“文档已生成，需用户复制更换，当前人格未修改”。
