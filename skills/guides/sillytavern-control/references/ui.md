# 界面操作

只有用户已授权操作指定原版酒馆页面、且存在运行桥与活动页面时才使用。后台语义工具足以完成的操作优先走语义工具，不为了检查后台对象主动打开浏览器。

## 前置条件

通过 `st.bridge.health` 和 `st.bridge.read` 确认桥及页面状态。MCP 可连接不代表浏览器已连接。桥协议 v2 需要对应服务端插件和前端扩展；`st.bridge.install` 会安装可执行组件，安装、重启和刷新应在用户已确认的范围内进行。

本技能不自动启动 Computer Use、Playwright、CDP 或另一浏览器控制工具。桥不可用时报告缺口；需要另一种操作方式时先说明并征得用户同意。

## 观察、动作、等待

1. `st.ui.observe` 获取当前控件、`actionId` 与 `clientId`，核对目标页面，不自动选最近发布的另一标签页。
2. `st.ui.act` 使用刚观察到的 `actionId`；状态变化在已有用户授权范围内传 `confirm: true`。开关使用明确的 `checked`，选项使用真实值。
3. 同次动作带 `wait`，或调用 `st.ui.wait` 等待预期变化，再读取结果。点击返回不证明保存完成。
4. 刷新、导航或大幅重绘后重新观察，旧 `actionId` 不能继续当作有效目标。

不在文档中硬编码坐标或依赖某版本按钮顺序。第三方插件控件也需真实发现，不因桥可以观察页面就承诺插件一定可运行。

## 能力边界

`st.ui.audit` 只审计当时已存在的页面控件，不证明所有抽屉、延迟界面或动作已通过。跨域 iframe、关闭的 shadow root、浏览器工具栏、系统文件选择窗口及要求可信用户事件的控件，可能不受桥支持。原生文件上传可用工具声明的 `upload` 动作时只提供用户授权的文件；不要绕过系统授权或把敏感文件当默认素材。

工具会对部分敏感控件脱敏，不保证整页任意文本都已安全处理。对外展示截图、表单或状态前继续核对私人内容。界面限制不通过任意 JavaScript 或修改页面源码绕过。
